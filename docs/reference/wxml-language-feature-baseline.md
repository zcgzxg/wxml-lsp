# WXML 语言功能基线

更新日期：2026-11-22。

本文件是本项目 WXML 通用语言能力的自有需求基线。功能取舍、默认行为和验收条件以本文为准，不再依赖外部插件的 README、源码或本机实验目录。

本文件只规定行为基线、数据来源和验收要求，不追踪当前是否已实现；当前能力、完成度与已知限制以[项目 README](../../README.md#能力摘要)为准，代码和默认运行的测试是最终事实来源。

## 1. 优先级与范围

1. 先完成 T1–T9 模板类型闭环：真实类型、字段说明、精确诊断、模板作用域、条件窄化、项目类型上下文和未保存一致性。
2. 在类型闭环可验收后，按日常使用价值补齐 F-01–F-18 通用语言功能。
3. 每项功能必须说明数据来源、支持范围、降级行为和验收样本。不能只以“补全列表非空”或“hover 有返回”作为通过条件。

首阶段只面向原生微信小程序 `.wxml` 及其关联 JS/TS、JSON、样式文件。Vue/Pug 内嵌模板、Emmet、一键创建组件、JS 变量自定义装饰、自动修改编辑器配置、扩展市场发布和上游 PR 工作流不属于需求。

| F-10 | 诊断 | 标记未知字段、非法类型操作和不兼容绑定；范围精确，修复后清除 | 类型后端、模板语义、诊断策略 |
| F-11 | Class 补全与导航 | 从同名样式文件和配置的全局样式补全 class，并展示注释说明 | 项目样式索引 |

| F-13 | 闭合标签与配对 | 开始/闭合标签补全、标签配对高亮；linked editing 只作用于同名标签对；不提供 on-type 自动闭合或标签重命名，不破坏 `wxs` 与表达式 | Zed 查询、必要的 LSP 编辑 |
| F-14 | Snippets | 提供内置片段和用户片段；占位符跳转与说明稳定 | 本地片段定义、用户配置 |
| F-15 | 格式化 | 保真格式化；解析失败时不修改文件 | 语法树、格式化器 |
| F-16 | 配置、依赖、缓存 | 默认零配置发现项目根、页面/组件归属；配置变更和依赖失效；内存覆盖层优先；显式 `apps` 固定边界 | 项目模型、文件监听、LSP 协调器 |

## 3. 行为细则

### 3.1 标签、属性和值（F-01–F-05）

- 标签补全在 `<` 后触发，候选至少覆盖微信小程序基础组件。候选项带一句用途说明；选中后保留用户已输入的前缀，不自动添加未请求的属性。
- 属性补全在标签名后的空白处触发，按当前标签或自定义组件的声明过滤。已经出现的属性默认不再重复推荐；允许同一属性多次出现的场景需有显式规则。
- 属性名匹配同时支持源码中的写法和元数据中的规范名，例如连字符与驼峰之间的对应关系必须确定，不能依赖模糊字符串搜索。
- 属性值补全只在枚举值明确时提供，例如 `picker` 的 `mode` 及其相关属性。替换范围覆盖原值内容，不残留引号或半截值。
- 条件筛选规则必须数据化，不能把 `picker` 等特例硬编码在补全流程里。规则至少能表达“某属性取某值时，另一属性可用/不可用/改变候选”。
- 指令和事件补全使用独立分类：`wx:` 指令、`bind*`/`catch*`/`capture-bind*`/`mut-bind*` 事件、普通属性。事件名与处理函数补全走不同请求通道，避免把属性候选混入表达式成员。

### 3.2 自定义组件（F-06）

- 从最近的页面或组件 JSON 读取 `usingComponents`，解析本地路径、绝对路径和项目支持的包形式。
- 组件标签候选优先于同名基础组件；出现重名时保留两者并标注来源，不静默取第一个。
- 组件属性优先来自项目 `tsconfig.json` 同级的 `components.d.ts` 声明；声明缺失或结构不完整时才回落到脚本 `properties`。无法解析、插件组件、远程组件或声明不完整时，明确标记为降级，不伪造属性列表。检查边界见[模板类型诊断策略](type-diagnostics.md#7-属性绑定与事件)。
- 配置未保存时以内存内容为准；组件文件或属性声明变化后刷新引用它的模板。
- 重复声明、循环引用和缺失目标文件必须可诊断，不能让补全或诊断流程崩溃。

### 3.3 表达式、Hover 与定义（F-07–F-09）

- `{{ }}` 内按模板作用域解析：页面/组件数据、组件属性、`wx:for` 项与索引、自定义循环变量、模板调用上下文、`wxs` 模块。模板体不保证逐调用实例化检查。
- mustache 以 `{` 开头的表达式按对象字面量检查：`{{ { elementId: ElementIdConfig.AICreateForm, name: user.name } }}` 在 shadow 中挂载为加括号表达式，对象 key 不产生“找不到名称”或“缺少分号”诊断，key 的 value 仍按正常表达式检查并映射回原位置。
- 尾点成员补全按模板作用域解析完整前缀：`{{ item. }}`、自定义 `wx:for-item`、`{{ item.Setting. }}` 和 `{{ user.name. }}` 都返回对应类型的成员；同名 `wx:for` 局部变量遮蔽脚本 data 根，替换范围只覆盖点号后已输入的标识符。
- WXS 模块点号补全：`{{ m1. }}`（含点号后的空格、制表符或换行）返回 `module.exports` 的静态导出，候选 detail 为签名或类型、documentation 为非空 JSDoc；`{{ m1` 同时补全模块名；动态导出或索引截断标记不完整，由 `semantic_surface.rs` 的真实 stdio 用例覆盖。
- 页面/组件的数据根来自脚本声明：页面为 `data`，自定义组件为 `data` 与 `properties`；字段在 WXML 中直接作为顶层标识符访问。独立 `interface`/`type` 只有被 `data`/`properties` 字段引用时才参与，不能作为模板根。
- 成员补全使用真实类型，不用正则枚举字段。`any`、`unknown` 和缺失类型必须显示真实状态，不能生成看似确定的候选。
- 事件属性中的处理函数补全来自脚本声明：`Component` 读取 `methods`，`Page` 读取选项对象上的函数；方法引用、`data-*` 参数和绑定形式分别处理。
- Hover 至少包含类型、字段说明和声明归属。字段说明优先使用实际 `data`/`properties` 字段或其引用类型自身的 JSDoc；没有说明时明确省略，不复制其他字段的文档。
- 定义跳转优先返回原始声明，而不是内存检查视图中的辅助符号。无法安全反向映射的编辑或位置不返回。
- 资源路径和 class 的定义跳转见 F-11、F-12；组件标签跳转到组件文件或声明入口。

### 3.4 诊断（F-10）

- 诊断范围映射回原始 WXML，精确到出错字段或表达式片段；中文、emoji 和不同换行格式不能导致偏移。
- 未知字段、非法成员访问、非法操作数和可判定的绑定类型不兼容是首阶段重点。模板运行时转换、可空访问等规则必须有独立策略，不能直接照搬 TypeScript 诊断。
- 只发布可归因到 WXML 的问题；辅助代码、检查视图包装和探针声明产生的错误属于桥接失败或覆盖不足，不能过滤后当作“检查通过”。
- 修复后旧诊断必须清除。后端不可用、检查关闭或只完成部分分析时，显示对应能力状态，不把空诊断当作严格通过。
- 诊断去重以“源文件、范围、代码、消息类别”为键，避免同一问题因多个检查视图重复发布。

### 3.5 样式与资源（F-11–F-12）

- Class 补全读取同名 WXSS/SCSS/CSS、`app.wxss`/`app.scss`、显式 `wxml.globalStyles`，并按页面/组件的 `styleIsolation` 过滤；不假设固定文件名一定存在，也不自动扫描用户目录。
- class 说明来自样式声明前的块注释；注释掉的 selector 不算定义。支持静态 `@import`/`@use`/`@forward` 链、逗号列表、复合 selector、可证明的 SCSS 嵌套/`&` 展开；动态插值、mixin/`@extend` 生成类和预算截断明确降级，不伪造完整结果。
- 资源链接只处理可证明的本地资源属性，并通过项目根和解析根计算目标；`http(s)`/`data:`/`wxfile:`/`cloud:` 等远程值与 mustache 不变成可点击链接。目标不存在时不生成链接，并按配置发布存在性诊断。
- 路径解析必须限制在项目可解析范围内，不因绝对路径、`..` 或符号链接越出预期工作区而不提示；资源扫描、class 数、导入深度/文件数/总字节均有独立预算。

### 3.6 编辑体验（F-13–F-15）

- 闭合标签、开始标签补全和 `</` 栈候选由 LSP/语法树提供；Zed 的括号、引号、Mustache 配对继续由语言配置负责。linkedEditingRange 只返回同名标签对；`rename` 只对已证明安全的目标生效，普通 tag 与自定义组件 tag rename 仍保守拒绝，不能把 linked ranges 或局部 rename 当作标签重命名。不提供 LSP on-type 自动闭合；跨文件事务、原子提交和 undo 见 §3.9。
- 编辑必须保持原文空白、注释、表达式和 `<wxs>` 内容。格式化只改写开始标签内部的 ASCII 空白，不重新打印整份文档；文本节点、实体、属性值、引号、属性顺序和重复属性逐字保留。
- Snippets 区分内置和用户定义。用户条目按 `id`/`label` 覆盖内置；占位符顺序、编辑后文档可重新解析和最终光标位置必须有测试。只有客户端声明 `snippetSupport` 且插入位置安全时才提供 snippet，否则回退普通候选。只读取 `snippetsPath` 或 `.wxml-lsp/snippets.json`，不读取编辑器私有配置，也不提供片段包市场。
- 格式化必须幂等、保留语义，解析失败、截断或存在未恢复语法错误时返回零编辑；rangeFormatting 只处理完全落在请求范围内的开始标签。多行标签中段无法安全推导缩进时跳过，不扩大到未请求文本。

### 3.7 项目与状态（F-16–F-18）

- 项目模型负责文件身份、内存覆盖层、磁盘回退、配置候选和依赖图。语言服务协调器是文档状态的唯一写入入口，分析只读不可变快照。初始化时的根选择与显式 `apps` 需要重启才改变；`app.json`、`tsconfig.json` 和工作区内容会按请求重新发现。完整多 workspace、跨 app 自动依赖归属和根热更新不在当前基线。
- 未保存的 WXML、脚本、导入类型和 JSON 配置优先于磁盘内容；关闭文档后回退到磁盘并产生新的内部版本。
- 默认零配置：从当前 WXML 分别向上查找最近的 `app.json` 与最近的 `tsconfig.json`，两者可以不同级；工作区根作为 `projectRoot`，向上不越过工作区，也不扫描 `node_modules`。默认从根 `package.json#workspaces` 或 `pnpm-workspace.yaml` 发现候选包，只挂载 app 依赖中命名的包。显式 `initializationOptions.apps` 固定 `root`/`projectRoot` 边界，不再向上查找。无法确定时显式标注推断状态。实现见 `crates/wxml-lsp/src/project_host.rs` 的 `discover_app_for_path`。
- 依赖变化只刷新受影响的模板。旧请求、旧快照和旧后端世代的结果不得覆盖新文本。
- 多工作区、多小程序根、多 `tsconfig` 和服务重启必须隔离；日志至少包含实例、事件和版本标识。零配置惰性发现与显式 `apps` 都要保持单 workspace 内的多 app、多 tsconfig 和重启身份；完整多 workspace 仍是后续需求，不能按已实现描述。
- 缓存键包含文档版本、项目版本、检查视图版本和后端世代。缓存失效条件必须可测试，不能只按文件路径缓存。

### 3.8 补全来源与静态目录

标签名、属性名、枚举值和指令/事件补全由版本化元数据驱动，是**静态、同步**的 Rust 路径，不调用类型引擎；表达式成员、事件处理函数和 WXS 成员补全走各自的查询或脚本事实通道。静态目录是**有意限定的子集**，不是官方组件表的自动镜像：未收录的标签、属性仍可用于模板，只是没有静态候选。

目录以代码和测试为准：条目定义在 `crates/wxml-lsp/src/completion/catalog.rs`，行为由 `crates/wxml-lsp/tests/component_intelligence.rs`、`crates/wxml-lsp/tests/structural_editing.rs` 与 `crates/wxml-lsp/tests/semantic_surface.rs` 覆盖。本文只记录规则，不再维护第二份逐项目录；新增条目时同时补测试。

规则：

- 标签补全在 `<` 后给出基础组件候选；属性补全按标签、自定义组件声明和已有属性过滤；值补全只对枚举明确的属性生效；指令与事件使用独立分类。
- 条件筛选规则必须数据化，至少覆盖 `picker` 各 mode 与 `input` type；未知或动态 mode 保留合法候选，不把特例硬编码进补全流程。
- 闭合标签补全（`</`）只来自当前未闭合元素栈，不给出其他标签。
- 所有候选项都带精确 `textEdit`：标签名和属性名只替换已输入 token；引号内的值只替换值前缀（保留引号）；未加引号的值插入带引号的字面量。不整行替换。
- 在纯文本、HTML 注释、`<wxs>` 元素体和 Mustache 字符串字面量内不产生补全；非模板文档（`.ts`、`.json` 等）经项目路由判定后直接返回空列表。
- `initialize` 无条件声明 `completionProvider`，`resolveProvider: false`，触发字符为 `<`、空格、`:`、`"`、`'`、`.`、`{`、`=`；结果 `isIncomplete: false`，单次最多 256 项。参数缺失或结构非法返回 LSP `-32602`。

#### 3.8.1 补全来源

- **表达式成员**：`{{ user.na }}`、`{{ item. }}` 由进程内类型会话按模板作用域解析真实类型后查询成员；`any`、`unknown` 和缺失类型如实返回状态，不用正则枚举字段。尾点与链式前缀的替换范围只覆盖点号后已输入的标识符。
- **事件处理函数值**：`bindtap="on"` 来自 Rust 侧脚本事实——`Page` 选项对象上的函数或 `Component` 的 `methods`，不调用类型引擎；注册容器名（`data`、`properties`、`methods` 等）不进入候选。路由规则：属性名以 `bind`、`catch`、`capture-bind`、`capture-catch`、`mut-bind` 开头且后缀为 `:` 或事件名时按事件值处理，因此目录未逐一列出的 `bindcancel`、`bindcolumnchange` 等也能得到方法补全；`binding-mode` 之类普通属性不受影响。
- **WXS 成员**：`{{ m1. }}`（含点号后的空白）返回 `module.exports` 的静态导出，候选 detail 为签名或类型、documentation 为非空 JSDoc；`{{ m1` 同时补全模块名。动态导出或索引截断标记不完整，不猜测。
- **静态目录**：标签、属性、枚举值、指令与事件来自本地元数据，不经过类型引擎；目录缺失的条目只是没有候选，不影响模板可解析性。
- 上述通道互不替代：后端不可用、超时或不支持时，相应通道返回空列表并记录原因，静态目录补全不受影响。这些通道并非都调用类型引擎，不能用一个通道的结果推断另一个通道已检查。

#### 3.8.2 已知边界

- 自定义组件标签来自页面/组件自身的 `usingComponents` 与 `app.json` 全局表；同名时页面/组件本地项生效，组件自身 WXML 也参与解析。组件属性名、类型、JSDoc 与事件参与补全/hover/definition；属性事实优先使用 `tsconfig.json` 同级的 `components.d.ts` 声明，声明缺失或结构不完整才回落到脚本 `properties`，详见[模板类型诊断策略](type-diagnostics.md#7-属性绑定与事件)。
- 插件或远程组件缺少本地可信元数据时明确降级，不伪造属性；运行时不在工作区下载或执行这些组件。
- 静态目录仍是手写受限子集，不是官方组件表的自动镜像；`picker`/`input` 之外的 mode 条件规则尚未数据化。
- class、资源和 WXS/template 的补全使用各自的索引/静态语义，不并入本节的标签目录；降级边界见 §3.3、§3.5、§3.9 与[模板类型诊断策略](type-diagnostics.md)。

目录溯源：条目定义在 `crates/wxml-lsp/src/completion/catalog.rs`；目录不下载、不执行外部元数据。

### 3.9 语义工具与安全编辑

- references 和 rename 的请求目标只接受已打开的 WXML；编辑可以落到关联脚本。跨 app、插件/远程组件和无法解析的目标不推断。
- references 只有在覆盖完整时才返回 `Location[]`；`wxml.references` 命令额外返回 `coverage.status`，不完整返回 `partial` 或 `unsupported`，不把部分结果当完整。rename 的覆盖不完整时整份拒绝，不生成部分编辑。
- `EditPlan` 必须满足：只使用 `documentChanges`；打开文件带客户端 version，关闭文件重读并以 `version: null` 返回；校验 expected 原文、UTF-16 范围、文件身份、去重、不重叠和可写路径；失败零编辑；服务端不写盘。
- 保守拒绝包括：自定义组件 tag rename、静态 include 导致的 caller 覆盖不完整、动态访问、共享 importedData 跨脚本、文件含 `<template name>` 时的页面 data rename、快照截断/超限、跨视图冲突、保留字、作用域捕获和对象 shorthand。未落盘 WXML fail-closed。
- codeAction 只提供字段拼写 quickfix 和创建事件 handler；Component `methods` 插入必须保持逗号语法有效。不提供 refactor 或通用代码生成。
- semanticTokens 使用 UTF-16，覆盖 CRLF、emoji 和 WXS 静态 token；只对可完整解析的模板生成，异常/超限返回空 token 流。workspaceSymbol 聚合多 app 和 static imported template，索引不完整时返回空并写日志。
- inlayHint、signatureHelp 和 codeLens 都基于静态事实；inlayHint 与 codeLens 默认开启，可通过 `initializationOptions.semanticTools` 关闭。codeLens 的 template/组件计数有上限，include 计数带当前文档锚点并明确 included 数量。
- 不提供跨文件事务、原子提交或 undo；硬链接未检测。symlink 和生成目录已拒绝，但不等于完整文件身份安全。

### 3.10 调度、性能与恢复边界

- 单后台 worker 串行执行后端请求；TypeScript 同步调用不可中断。取消只保证排队请求立即响应，
  运行中请求必须等后端返回；`Deadline` 只在送入引擎前检查，运行占用单独测量，不能当作取消延迟。
- 诊断 debounce 默认 120 ms，可通过 `wxml.diagnostics.debounceMs` 设 0–5000 ms；打开、保存和
  配置变更绕过 debounce。同一文档只保留最新 revision，旧结果不得发布。
- 交互队列上限 128、诊断队列上限 8；连续 8 个交互任务后必须让诊断前进；队列满时明确报告
  busy，不无限排队。诊断重试最多 8 次。
- 超时、会话死亡或协议失败时降级并保留静态能力；当前请求最多重建一次会话，失败仅让当前请求失败并丢弃会话，后续请求仍可按同一规则重建。没有通用重试或服务器进程重启。根移除/重加重放已打开的 WXML 和 script/JSON/style overlay；单 active root，多 app 重放
  受 active project 限制，不支持多根热加。
- 本文件不记录历史性能、RSS 或 release 构建数字；需要引用时必须现场复测，并同时说明硬件、
  fixture 规模、冷热状态和测量区间，见[查询基准](benchmarks.md)。单 fixture 的数字不能外推为
  大项目语料或真实编辑器 UI 的结论。
- 平台验证范围以[项目 README](../../README.md#已知限制)为准；没有 marketplace、远端 release 或
  发布者签名，不能从本地安装推导出这些能力。

## 4. 数据来源与元数据规则

允许的数据来源：

1. 仓库内版本化的基础组件、属性、指令、事件和片段元数据。
2. 项目内的 `app.json`、页面/组件 JSON、`usingComponents`、`tsconfig`、样式文件和用户片段配置。
3. 脚本类型、JSDoc、声明位置与组件 `properties` 的静态事实来自类型会话或 Rust 脚本分析；组件属性/事件优先使用 `tsconfig.json` 同级的 `components.d.ts` 声明，声明缺失或结构不完整才回落到脚本 `properties`；数据根限定为页面/组件 `data` 与组件 `properties` 及其引用类型，组件声明见[模板类型诊断策略](type-diagnostics.md#7-属性绑定与事件)。

约束：

- 运行时不依赖外部插件、外部仓库或临时目录。缺少本地元数据时功能降级并报告，不静默下载。
- 每条内置元数据记录应能追溯到来源、版本和许可证；功能文档不把外部项目当作需求依据。
- 元数据结构至少包含：规范名称、别名、适用标签/组件、值类型、枚举值、条件规则、说明、来源版本。
- 不执行工作区脚本或 `new Function` 提取组件信息；需要脚本语义时交给类型后端做静态分析。
- 不把生成代码写入业务项目。检查视图、辅助符号和缓存均存在于内存或项目自有缓存目录。
