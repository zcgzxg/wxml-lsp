# 现有 Rust WXML LSP 核验（2026-11-15）

## 对象与环境

- 被核验对象：现有 Rust WXML 语言服务，版本 `0.1.9`，提交 `84425dad66de0991e0cdf24e9c86842dc8209cdd`。来源与许可证见[来源记录](../reference/provenance.md)。
- 核验方式：构建该服务，使用独立 LSP 探针发送真实文档与 hover/诊断请求；同时运行其自带测试。
- 业务项目：未修改。

## 方法

- 33 个独立场景，共 66 次 hover 请求。
- 样本覆盖局部类型、字面量、相对导入、别名、命名空间导入、路径别名、传递接口、重导出、前向声明、联合类型、循环作用域、组件属性、未保存文档和 Unicode 位置。
- 运行被核验仓库的测试套件，记录通过数量。
- 原始结果、探针和测试日志均已保留。探针需要先构建被核验服务的二进制；本仓库不包含该二进制。

## 结果

### 自带测试

四组测试共 112 项通过，0 项失败。构建日志记录开发构建耗时 21.98 秒。自带测试通过只说明该版本内部测试成立，不等于满足本项目验收。

### 可工作的基础场景

- 局部接口和字面量对象的字段 hover 能返回类型。
- 简单相对导入、类型别名、嵌套字段和部分循环变量能返回类型。
- 基础组件属性（布尔、数字、字符串、可选值）能返回类型。
- 中文位置的 hover 能落在预期字段上。
- 未定义字段能产生诊断。

### 主要缺口

| 场景 | 观察结果 |
| --- | --- |
| 字段 JSDoc | 所有 hover 只显示类型和父对象，没有字段说明 |
| 命名空间导入 | `user` 退化为 `unknown`，成员 hover 为空 |
| 路径别名 | `user` 能显示别名类型，但成员 hover 为空 |
| 传递接口、重导出 | 父对象有类型，成员 hover 为空 |
| 前向嵌套、内联类型 | 父对象退化为 `{}` 或 `unknown`，成员为空 |
| `const` 断言、导入后再断言 | 部分字段丢失 |
| 可空与判别联合 | 即使在 `wx:if` 分支内也常退化为 `unknown` |
| 泛型 Page/Component | 数据上下文退化为 `unknown` |
| 异构数组循环 | 元素为 `unknown`，成员为空 |
| 循环作用域退出 | 循环外的同名 `item` 仍被当作循环变量，存在泄漏/遮蔽错误 |
| 属性绑定类型 | 不检查绑定值与被绑定属性的兼容性，错误绑定没有诊断 |
| 未保存脚本 | 脚本未保存改为新类型后，模板 hover 仍是旧类型 |
| 诊断精度 | 不支持的形式常被简化为“未定义变量”，不是精确类型错误 |

## 限制

- 33 个场景集中在类型与作用域，不覆盖完整 WXML 语法、格式化、补全和所有组件写法。
- 探针以 hover 和诊断为主，未验证 Zed 端到端行为、未保存事件顺序和多服务并存。
- 结果只代表上述版本和提交。上游后续版本可能变化。
- 没有复制被核验仓库的源码或测试样本，只保留探针、场景定义和输出。

## 对项目的影响

可以借鉴其解析、基础 LSP 协议和部分作用域处理经验，但不能把其类型分析层作为本项目的准确类型来源。字段说明、跨文件类型、联合类型、循环作用域退出、属性绑定和未保存同步都需要本项目独立实现与验收。这支持[ADR-0001](../adr/0001-layered-language-service-architecture.md)中“Rust 专注模板与编辑器集成、类型交给完整 TypeScript 后端”的分工。
