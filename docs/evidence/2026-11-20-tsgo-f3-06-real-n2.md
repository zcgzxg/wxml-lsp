## 0. 结论先行

F3-06 的 provenance 子条件已由两个**独立真实构建**的 native release 关闭：

- N1 = `0.1.0`，从 clean `git archive HEAD` 源码重新编译、重新打包；
- N2 = `0.2.0`，同一 clean 源码树只把 workspace 版本改为 `0.2.0` 后**重新编译**
  （不是复制 N1 二进制后改版本字符串）；
- 两包的 archive、`bin/wxml-lsp`、`bin/wxml-lsp-install`、manifest、provenance 均不同；
- 两个包都通过生产 `wxml-lsp-install verify-package`；
- 生产 CLI 完成 `install N1 -> upgrade N2 -> rollback N1 -> recover`，N1/N2
  installed tree 指纹全程不变；
- 篡改 N2 archive 或 N2 manifest 时，升级在激活前失败，N1 的
  `current`/`state.json`/tree 不变；
- `f3_kill_window` 的 F3-06 六个真实 CLI 用例（U1/U3/U5/U5-durable/U6 + 控制）
  全部改用该真实 N2 包并通过；`scripts/f3-kill-window.sh` 整体 PASS（同次运行
  F3-09 L3/L4 也保持 PASS，未修改 F3-09 语义）。

因此 F3-06 可按合同升为 **closed**。本文件只记录真实构建/安装/中断验证；

## 5. N2 升级失败时 N1 不变

两个失败用例都从干净 root 安装 N1 后执行 `upgrade --from-dir <tampered-channel>
--offline`；失败后 `current=0.1.0`、`state.json` 字节与升级前相同、N1 tree
指纹仍为 `2e306f9c...8a8d`、`versions/` 只有 `0.1.0`、`txn/` 为空。

### 5.1 篡改 N2 archive

在真实 N2 archive 末尾追加 1 字节，保留原 index：

```text
$ ... upgrade --root ... --from-dir /tmp/opencode/f3-06-real/bad-archive --offline
error: package integrity check failed: local release archive size does not match the index
exit=1
```

日志：`/tmp/opencode/f3-06-real/bad-archive-upgrade.{out,err}`。

### 5.2 篡改 N2 manifest（重打包并重算 index）

解包真实 N2 archive，把 `manifest.json` 的 `packageVersion` 从 `0.2.0` 改为
`0.2.1`，同步 `SHA256SUMS` 的 manifest 行，重新打包并重算 index 的
`sha256`/`size`/`archiveIntegrity`。升级仍在激活前失败：

